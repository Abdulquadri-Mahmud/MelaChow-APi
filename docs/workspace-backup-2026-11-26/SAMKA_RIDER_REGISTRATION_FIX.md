# Rider registration audit — 20 October 2026

The screenshot message is generated by Samka-Rider when POST `/api/rider-auth/register` returns HTTP 503. Its support ID is `01a158ec-e8c8-7363-b241-1767e353f151`.

The relevant backend is the sibling repository `../Samkatech-Codebase/SamkaTech.Logistics`, not MelaChow-API-staging. Rider registration calls Samka directly. Bank verification already succeeded in the screenshot.

## Finding and repair

`RegisterRider.Handler` validated the existing bank proof, constructed a pending rider, then called Resend before saving the rider and code. Resend rejects unsuccessful provider responses with `ExternalServiceException`, which middleware maps to HTTP 503. This is the identified code path consistent with the screenshot; the exact deployed provider rejection has not been confirmed from logs.

The backend now saves the pending rider and verification code first. Provider, network and timeout failures are logged with the rider ID and return `verificationEmailSent: false` instead of losing registration. Email verification and admin approval remain required. The rider frontend carries this result to the verification screen and explains how to resend. Resend normalizes email and saves its new code before sending it, preventing successful email delivery of a code that was never persisted. No schema migration is required.
